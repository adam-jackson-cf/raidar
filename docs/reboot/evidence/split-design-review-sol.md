## Findings

Paths: `R/` = `orchestrator/src/raidar/`; `F/` = FXL’s `src/factory_x_loops/`; `H/` = `orchestrator/.venv/lib/python3.13/site-packages/harbor/`.

1. **blocker — Strip deletes infrastructure, not just treatments.** [OBSERVED] Phase 1 deletes the treatment runtime before phase 3 supplies its replacement (`docs/reboot/split-design.md:170-172`). Every arm uses its checkpoint reset; the reaper imports its setup constants; materialisation applies its compiled condition (`R/subject/treatment/runtime/setup_script.py:1-15`, `R/engine/health/reaper.py:34`, `R/engine/trial/materialise.py:99-122`). Deleting gate-effort also leaves live review imports (`R/evaluation/review/quality/gate_view.py:30-42`).
   **Fix:** [INFERENCE] Move lab-owned reset/setup infrastructure first; land minimal one-shot schema, lock, and execution support atomically with removal; migrate or remove every remaining consumer in that cutover.

2. **blocker — Deleting the “harbor adapter” breaks both retained adapters.** [OBSERVED] `HarborCliAdapter` is their superclass, not a removable registered arm (`R/subject/agent/adapters/harbor_cli.py:17-18`, `codex_cli.py:10-13`, `claude_code_cli.py:6-8`). The deletion wording includes “harbor” (`docs/reboot/split-design.md:49,170`).
   **Fix:** [INFERENCE] Name the exact removable modules; retain or first relocate the shared installed-agent implementation.

3. **major — The existing wrapper’s log handling is incompatible with native resume.** [OBSERVED] It creates a new inner agent, calls `run`, and moves root session logs into each stage directory (`R/subject/treatment/runtime/guardrail_gate.py:356-413`). Harbor Codex resume requires root `sessions`, restores it into `CODEX_HOME`, uses `resume --last`, then deletes that home (`H/agents/installed/codex.py:1415-1475`). FXL explicitly carries the builder’s returned session (`F/engine/workflow/verified.py:344-376`).
   **Fix:** [INFERENCE] Specify active-session storage separately from immutable turn logs and call Harbor’s resume API. Prove fix and rework resume the builder—not define—and the next checkpoint starts fresh, for both retained harnesses.

4. **major — Copying wrapper accounting will double-count resumed usage.** [OBSERVED] Current wrappers sum every context (`R/subject/treatment/runtime/review_loop.py:331-340`); Harbor Codex contexts receive cumulative trajectory totals (`H/agents/installed/codex.py:1091-1137,1158-1194`). FXL explicitly deduplicates cumulative usage by session (`F/harness/codex.py:101-159`).
   **Fix:** [INFERENCE] Record per-turn deltas and nonduplicated trajectory slices; retain session totals as reconciliation evidence. Require a multi-turn accounting exit criterion.

5. **major — The fixed delivery rule does not cover instructions or removal between stages.** [OBSERVED] Instructions are a component kind, but the delivery table only specifies skills (`docs/reboot/split-design.md:27,55-61`). FXL installs its workflow-wide skill set before execution; its placement loop replaces named folders, not other existing folders (`F/engine/lifecycle/workspace.py:186-230`). Harbor additionally copies skills into harness-home locations (`H/agents/installed/codex.py:1196-1205`, `claude_code.py:1628-1638`).
   **Fix:** [INFERENCE] Define instruction placement/composition and stage-boundary cleanup across workspace and harness-home copies. Prove define-only content is absent from build and disabled-stage content never arrives.

6. **major — The graded tree after interruption is unspecified.** [OBSERVED] The design seals completed turns but states no cancellation restoration rule (`docs/reboot/split-design.md:59,135`). FXL restores the last decided gate tree when a deadline cuts a turn (`F/engine/workflow/verified.py:630-642`). Raidar’s V3 only establishes agreement between the graded snapshot and recorded snapshot—not agreement with a gate (`R/engine/health/audit.py:115-152`).
   **Fix:** [INFERENCE] Define which tree survives timeout, cancellation, gate error, and exhausted fixes. Record the gate-to-snapshot relationship and exercise interruption during a fix; otherwise an ungated partial edit can be graded as the verifying workflow’s output.

7. **major — Liveness cannot remain unchanged during host-side judging.** [OBSERVED] Monitoring spans the entire agent phase and watches sandbox output, CPU, and network; after an idle decision it reaps the agent UID (`R/engine/health/liveness.py:3-24,315-331,409-425`). Jev requests run host-side (`F/capability/judge/jev.py:290-344`), while the design keeps this monitor unchanged (`docs/reboot/split-design.md:135`).
   **Fix:** [INFERENCE] Make monitoring stage-aware: host judge activity needs its own registered limit, not sandbox-idle classification. Exercise a prolonged judge wait followed by another builder turn.

8. **major — The health table is not an outcome-to-validity table yet.** [OBSERVED] Section 6 lists families, but supplies no per-check mapping for pass, violation, and unmeasured (`docs/reboot/split-design.md:139-150`). Current validity has independent execution checks plus selected health violations (`R/engine/trial/collect.py:336-381`); the finisher appends both (`R/engine/trial/finish.py:50-59`). FXL separately distinguishes a broken define tool from an unusable model definition (`F/evaluation/health/engine.py:307-334`).
   **Fix:** [INFERENCE] Settle the actual mapping before phase 4: migrate existing execution checks, distinguish instrument failures from agent outcomes, specify critical missing-evidence handling, and make health the sole validity producer.

9. **major — Identity omits named content and leaves pooling enforcement underspecified.** [OBSERVED] Section 5.4 explicitly hashes skill files but not instruction-file contents; the checks example leaves pytest and pytest-cov unversioned (`docs/reboot/split-design.md:124-131`). FXL hashes instructions explicitly (`F/engine/workflow/config.py:716-728`). Raidar’s pooling subject identity currently reads agent hashes only; execution-code differences are overridable (`R/evaluation/analysis/pooling.py:31-40,65-69,109-127`).
   **Fix:** [INFERENCE] Hash every delivered component, resolved tool lock, and transitive stage implementation. Specify execution-time freshness checks and pooling rules for those identities; preserve the existing broader execution provenance.

10. **major — The Jev port can contradict the no-retry infrastructure-failure rule.** [OBSERVED] FXL v2 configures three judge retries; its backend retries transport failures and returns unanswered judgements rather than ending the run (`FXL/workflow/define-build-verify/v2.toml:98-114`, `F/capability/judge/jev.py:17-25,250-344`). Raidar’s client returns typed failures (`R/scoring/judge/client.py:39-58,206-235`); phase 8 merely requires a judge call and recorded ending (`docs/reboot/split-design.md:177`).
    **Fix:** [INFERENCE] Specify the failure adapter explicitly: one failed judge request records infrastructure failure and invalidates the trial without re-asking. Test this after phase 8 introduces judging, not only during phase 4.

11. **major — Pilot-only run registration loses other migrated evidence.** [OBSERVED] Migration names pilot jobs (`docs/reboot/split-design.md:161`), but FCR-002/003 and M-001 cite guardrails main/smoke jobs and removed experiment prose (`lab/ledger/faults/FCR-002.md:7-16`, `FCR-003.md:7-13`, `lab/ledger/remedies/M-001.md:28-33`). FXL run records carry availability and digests (`F/evaluation/journal/schema.py:145-170`); today’s ledger check does not resolve evidence citations (`R/evaluation/ledger/check.py:87-111`).
    **Fix:** [INFERENCE] Inventory every cited run and source, capture excerpts/digests, resolve archive references, and verify migration completeness before clearing `var/`. After deletion, mark unavailable runs `gone`, not `local` or implicitly fetchable.
