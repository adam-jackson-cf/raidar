## 1. Verdict

There are more mistakes of the `reference_k-1_fails_k` class. The two most consequential ones change a verdict:
- **(A1) Verdicts on yes/no outcomes.** The primary outcome is treated as continuous even when it can only be 0 or 1. That is always true on one-checkpoint problems, including the lab's benchmark problem. A paired t-test or bootstrap then reports `improved` where the exact McNemar test reports `inconclusive`. Five pairs that all move the same way give a zero-width interval.
- **(A2) The spec-determinacy audit.** It reports "0 flagged" on problems where it audited 0 assertions. Separately, the cases it does flag still count against agents in the primary outcome.

Five more mechanisms rest on assumptions the real data contradicts:
- **Flake detection.** It is measured on the reference code only, and agents are graded once.
- **Grading crashes.** When the submission crashes the grader, it is classed as infrastructure, so the trial is dropped rather than scored as a failure.
- **Per-arm exclusions.** The design's per-arm exclusion rule is not implemented.
- **`halt_on_failure`.** It decides on the raw grade while scoring uses the solvable set.
- **Grader identity.** The grader a problem was validated under is never compared with the grader used for grading.

The lower-level grading machinery is sound: case normalisation, the ledger cross-checks, the pytest isolation flags, McNemar, pooling identity, the tamper checks and the reaper.

## 3. Checked and judged sound

- **Case normalisation** (`normalise.py:31-42`) matches the fork's `classify_test_group`. No pinned problem declares custom markers [OBSERVED].
- **`case_key` and the strict solvable rule** (`grading/solvable.py:28-42`): no id collisions, since every pinned test file is `test_checkpoint_N.py`. A missing or skipped case counts as not passed.
- **Ledger and exit-code cross-checks** plus the corpus check (`normalise.py:75-107`) and the pytest isolation flags `-c`, `--rootdir`, `--confcutdir` (`sandbox.py:119-131`).
- **Pooling:** jobs must share `lock_sha256` (`sources.py:219`); solvable sets sit inside the execution section (`problem/resolver.py:83`); records-manifest tamper checks always run. This covers T2 being `unmeasured` in 20/30 trials at audit time.
- **McNemar** (`stats.py:194`) and the equal-weight aggregate apart from A1.
- **Errata:** applied only from the lock; a digest mismatch makes the outcome `ineligible`.
- **Runtime gate RT0–RT6:** pins the manifest digest and a usable verdict (gaps in A7 and A8).
- **Lock sections and currency** (`lock.py:472-512`).
- **Liveness:** three signals plus host-activity windows, so host-side judge time is not counted idle. 0 idle kills in 30 trials.
- **Reaper:** 0 residual processes in every `agent-reap.json`.
- **Perf gate:** warm/cold is decided from image presence before the run (`run.py:79`), not from the timing being judged.
- **Admission:** a clean smoke must exist and the agent must have changed `/app`; leaving the problem out of the smoke identity is by design.
- **Setup check:** reads root-owned facts only and runs no agent code (`verify_gate.py:1133-1142`).
- **Judge thresholds and undecided-as-open:** they steer the treatment, not the measured outcome. D3 is a recorded decision.
