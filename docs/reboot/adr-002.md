# ADR-002: Mechanics v1: copy-only execution targets, run-health and the mechanics epoch

- **Status:** Accepted (user decision "go", 2026-10-23, on the recommendations for `mechanics-v1-design.md` r2 §8 decisions 1–8 and gaps C1–C3)
- **Date:** 2026-10-23
- **Authority:** `docs/reboot/requirements.md` (v1, frozen 2026-09-29) and ADR-001. This ADR amends ADR-001 §2.3 (verifier mechanics) and §2.7 (container runtime), and records reading notes on F4, F5, N1, N2, N3 and N4 in the requirements change log.
- **Design:** `docs/reboot/mechanics-v1-design.md` (r2; the Innovation Council review of r1 is summarised there). Second opinion weighed: `docs/reboot/split-exploration.md`.

## 1. Context

- The work Mac's OrbStack is off. Docker now runs on `adams-macbook-pro` (mbp) over Tailscale, a host shared with other projects (handoff 2026-10-23 §2.1). Raidar must also run on other people's machines and, later, on Harbor cloud environments.
- Harbor trials bind-mount host folders (`harbor/environments/docker/docker.py:323`, `mounted=True` hard-coded), and Raidar's grader runs `docker run -v` of host paths (`verifier/sandbox.py:219-226`). Against a remote daemon those paths resolve on the remote host and silently become empty folders.
- Every scorer's Assessment key hashes the transitive `raidar.*` import closure of its implementation (`scorers/catalog.py:125-144`). [OBS 2026-10-23, `.tmp/closure_probe.py`] That closure includes `verifier/grader.py` and `verifier/sandbox.py` (via `scorers/sdk/context → verifier/records → verifier/grader`) and `packs/python/{image,provisioner,harness,task_environment}.py` (via `scorers/builtin_manifests → packs/python/__init__` re-exports). So any edit to the grader sandbox or the pack image code re-keys every scorer.
- ADR-001 §2.7 fixes the container runtime to OrbStack on the work Mac, with its data on the UGreen drive.

## 2. Decision

### 2.1 Copy-only data path (amends ADR-001 §2.3)

- Trials run in Harbor's non-mounted mode (`capabilities.mounted=False`). Harbor downloads `/logs/agent` after each phase and `/logs/verifier` after verification. Raidar never bind-mounts host paths into trial or grader containers.
- The host-side verifier stays host-side (F4 is unchanged). Its sandbox copies the snapshot, hidden tests and runtime into a fresh locked-down container (`--network none`, uid 1000, `--cap-drop ALL`, tests and runtime root-owned and read-only), then copies the results out. Copying is stricter than mounting: nothing in the container can write to the host.

### 2.2 Execution targets (amends ADR-001 §2.7)

- The container runtime is a per-machine **execution target** (`~/.config/raidar/targets.toml`, no secrets, selected by `TARGET=`). It replaces the fixed OrbStack context. Kinds: `docker` now, `harbor` (cloud environment types) later.
- The UGreen precondition becomes a per-target `data_check`. The work Mac's `local` target keeps `orbstack-data-status`; mbp's internal SSD is accepted.
- Every job records the resolved target facts (`execution_target`) and the mechanics epoch. The target is not part of the experiment lock: the same experiment may run anywhere.

### 2.3 Trust boundary (reading note on F4 and N2)

- A target is marked `trusted: true` in the per-machine config. Raidar refuses to send hidden tests or agent credentials to a target that isn't trusted.
- With mbp as the trial or grader target, hidden tests *and* the agent's credentials (for example `/tmp/codex-secrets`, `harbor/agents/installed/codex.py:82`) sit on mbp for the duration of a trial. The user accepts this for machines they own on their tailnet.
- Hidden tests are never sent to a third-party provider: for cloud targets the grader target defaults to `local`.

### 2.4 Run-health (reading note on F5 and N3)

- The trial's validity is decided by a per-trial **health audit** (`health.json`, checks that return `pass`/`violation`/`unmeasured`) and by **host-side liveness monitoring**: Harbor's streamed exec output plus a root `/proc` poll, killing via the existing reaper, with the record written on the host.
- The liveness monitor terminates and classifies; it never retries. Retry-on-stall is subject method (harness or treatment) and wins inside its own window.
- Liveness runs in **observe** mode (recorded, no kill) until its threshold is calibrated and the user accepts enforcement.

### 2.5 The mechanics epoch (reading note on N3 and on the 2026-10-02 "kept byte for byte" rule)

- **Epoch `mechanics-v1`.** The pre-epoch HEAD is tagged `archive/pre-mechanics-v1`. Until v1 is declared, execution-path code (execution, environment, verifier sandbox, provisioning, pack image code) changes without per-change `@version` bumps or rationale amendments. Jobs from different epochs are never pooled.
- **One declared scorer re-key (step −1).** Cut the closure edges named in §1: the grader's data types move to a module that imports no sandbox code, and `packs/python/__init__.py` stops re-exporting its submodules. Every scorer's `implementation_digest` changes exactly once. All locks are relocked in the same change. Stored Assessments are rescored with `make experiment-assess`, which never re-runs agents; old Assessments stay in the add-only store. Value parity on a main-04 rescore is the regression check.
- **Released component bytes stay frozen.** The fingerprint sources listed in released manifests are not edited; `raidar/oracle/snapshot.py` keeps its bytes. Where the copy path makes a helper unnecessary (`make_world_writable`), Raidar stops calling it rather than deleting it.
- Where an epoch change alters a component digest (for example a `COMMON_FINGERPRINT` source), relocking changes `lock_sha256`. That is expected under the epoch: old jobs stay readable under their own `job.lock.json`, and locks made during the epoch hold no citable jobs.
- **N1 budgets** accepted on the work Mac stay as the reference. Budgets for another target come from that target's copy-path fixture runs and need user acceptance. Strict gating applies only to accepted budgets; everything else is report-only.

### 2.6 Guardrails series closed

The guardrails ab-test (`experiments/ab-test/python__forge__guardrails`) is closed as explore evidence: its jobs, locks and rationale are kept, and no further iteration runs on Raidar's 85% coverage gate. A future comparison of verify gates is a new estimand, with a new rationale and lock.

## 3. Alternatives considered

| Option | Why not chosen |
|---|---|
| Point Harbor at a remote daemon with mounts | Paths resolve on the remote host; results become silently wrong |
| Run Raidar itself on the Docker host (rsync jobs back) as the main route | Keeps mounts and a per-host checkout; kept as an optional later wrapper only |
| In-container root watchdog for liveness | Its record sits in agent-writable `/logs/agent`, which is emptied per step; it depends on a provisioning component that is a strip-list candidate; doubtful on cloud sandboxes (council review) |
| Migrate component fingerprints to exclude mechanics files | Impossible without editing released manifests, whose fingerprint tuples are themselves hashed (`components/registry.py:110-121`) |
| Re-key scorers whenever a mechanics edit lands | One re-key per edit, each needing a full rescore; one deliberate re-key is cheaper |

## 4. Consequences

- **Positive:** one data path for local, remote and cloud targets; a stricter verifier sandbox; scorer keys insulated from mechanics edits; validity decisions recorded per trial.
- **Negative:** one full rescore of every store; every lock is relocked; the trust boundary widens to owned remote hosts; per-target budgets must be accepted before strict perf gating.
- **Follow-ups:** step −1 evidence (closure probe before and after, main-04 value parity) is appended below. The spike (step 0) evidence is appended when it runs.

### A.5 Step 5: run-health (2026-10-23)

- **Liveness (`execution/liveness.py`, ported from `23c8b04`):** armed on every trial by `run_harbor_trial`, default `observe` (`RAIDAR_LIVENESS=observe|enforce|off`, `RAIDAR_LIVENESS_IDLE_S=600`, `…_INTERVAL_S=15`). Idle means no streamed output, no agent-uid CPU and no container network for the window; a failed poll is `unmeasured`. `enforce` is opt-in and kills with the reaper's uid script. Record: `<trial>/raidar-liveness.json`. It never retries; harness and treatment limits win inside their windows.
- **`health.json` (`execution/health*.py`, `raidar health JOB`, `make health JOB=`):** written per trial after classification and the target guard, before the trial record, so the record's validity includes it. `raidar health` recomputes it (the only point where `T2` can verify the sealed manifest) and exits 1 on a violation. `health.json` is outside the records manifest (derived, recomputable). Checks `{id, family, status, detail, evidence}`, `unmeasured` carries its reason:
  - V1 timed-out evaluator never a pass; V2 case counts agree (ledger summary, record, rewards); V3 stored `/app` tree digest = evaluated digest.
  - H1 record files present (`result.json`; per executed step `record.json`, `agent-reap.json`, `pre-agent-leak.json`); H3 effective limits recorded; H4/H5/H6 agent, agent-setup, verifier wall time within the effective limit plus a 60 s teardown grace (`unmeasured` when the limit is the task's own default); H-target mirrors the guard's `target_reachable`.
  - L1 liveness record per agent phase; L2 `idle_observed` is a *pass with a finding*, an enforce kill is a violation (`agent_idle`).
  - P2 concurrency (configured, effective, peak overlap); P3 comparison warnings from `job.json` (dirty runner, missing Docker facts, `ALLOW_UNSMOKED`, agent override).
  - T1 hash of `/opt/raidar-tools` plus the `/usr/local/bin` links into it (root exec; `.staging` excluded) before the first agent phase and after every agent phase, kept host-side in `raidar-tool-hashes.json`; T2 records manifest verifies; T3 reaper residuals empty.
- **Validity mapping (`collect.health_validity`):** one validity check per group, failed on any violation in it: `health_verdicts` (V1-V3), `health_budgets` (H1, H3-H6), `health_tamper` (T1-T3), `agent_idle` (L2). H-target is not mapped (the guard already adds `target_reachable`); L observe findings, P and `unmeasured` never invalidate. An audit that raises adds a failed `health_audit` check and keeps its traceback. Existing check names are unchanged and the new checks follow them.
- **Fault candidates:** every violation and every `idle_observed` appends `{trial, step?, check_id, status, detail, evidence, state: "provisional"}` to `<job>/fault-candidates.jsonl` (idempotent per trial, step, check and status).
- **Smoke-before-measure (`execution/admission.py`, `--allow-unsmoked` / `ALLOW_UNSMOKED=1`):** a non-smoke `raidar run` needs a finished smoke job under the jobs root whose toolchain digest, pack recipe, agent name/model/effort (the run's agents must be among the smoke's) and target name and Docker facts match, with every trial valid and every `health.json` free of violations. The decision (`admission`) goes into `job.json`. Smoke kinds are always admitted. The no-LLM perf fixture runs with `--allow-unsmoked`.
- **Calibration on mbp (no LLM):**
  - Docker liveness tests pass (hung → `idle_observed` at 22 s with a 20 s window; busy and chatty → `active`; enforce kills a hung agent and its `setsid` sleeper with no residual; a stopped container is `unmeasured`, never idle). A real two-step trial with a root edit of a provisioned tool gives T1 `violation` at the edited step only; an untouched one passes.
  - **Blackholed endpoint:** one `codex` smoke trial with `CODEX_AUTH_MODE=api`, a placeholder key, `OPENAI_BASE_URL=http://10.255.255.1:9`, idle window 60 s and a 300 s agent timeout (no model call can have been made). Codex logged `Reconnecting... n/5 (request timed out)`, fell back from WebSockets to HTTPS and ended on `Reconnecting... waiting for network`. Its retries kept output and network non-zero for about 120 s; liveness then recorded `idle_observed` at 182 s (60.8 s of quiet), and the trial ended at the timeout (`AgentTimeoutError`), a *valid, failed* trial. Observe mode flags it; nothing else does, so a long idle window (default 600 s) or enforce is the only classification of a dead endpoint. Falsifier "a blackholed endpoint is flagged idle per harness" holds for codex; claude-code is untested.
  - **Perf gate:** `make perf-gate TARGET=mbp` passes at concurrency 1 and 3 with liveness observing and T1 hashing on every trial. p95: per-step overhead 2.92 s / 3.14 s (budget 10 s), per-trial fixed overhead 2.70 s / 2.92 s (27 s), `raidar_result_write` 0.00 s (0.5 s), `teardown_result_write[init]` 0.83 s / 1.04 s (4 s). All 20 fixture trials audit with no violation (H5 and T2 are `unmeasured`: no agent-setup limit is recorded for the oracle override, and the manifest is sealed after the audit); `make health` on the job verifies T2 `pass`.
- **Open risks:** (1) the fixture has no provisioned tool tree, so T1 on a real component run is covered only by the two-step fixture above, and hashing a large tree (python-guardrails venv) after every step is not yet timed; (2) idle thresholds are uncalibrated for real codex runs (the blackhole shows the first ~2 min of retries look active); calibrate from main-03/04 rollout gaps before any `enforce`; (3) H4-H6 need recorded task-default limits to move from `unmeasured`; (4) `idle_observed` and a valid timed-out trial are indistinguishable from a slow agent until a ledger fault is attached; (5) the enforce kill invalidates the trial (`agent_idle`), which removes stalling arms from analysis; that choice awaits the user's acceptance of enforcement.

### A.6 Step 4: provenance and pooling gate (2026-10-23)
