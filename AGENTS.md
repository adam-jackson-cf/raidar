## Workflows

- Public interface: repo-root `make ...`
- Use `make help` for command discovery and target descriptions.
- Treat direct `uv run --project orchestrator raidar ...` as implementation detail behind the root `Makefile`.
- LiteLLM must stay exact-pinned to a known-safe release across manifests and lockfiles. Do not use `1.82.7` or `1.82.8`.
- Keep `README.md` as the only human entrypoint; do not duplicate exhaustive command lists in other docs.
- Vocabulary (schema v2, requirements change log 2026-10-02): use Harbor's terms wherever Harbor has one. A **job** is one execution of a locked experiment (`jobs/`, `job.json`, `job.lock.json`, `JOB=`/`JOB_ID=`/`JOBS_DIR=`); a **trial** is one arm × attempt × problem (was "trajectory"); a **step result** is one checkpoint of a trial; **attempts** are the paired, counterbalanced replicates (was "blocks"; `analysis.attempts`); the **verifier** is the hidden grader (was "oracle"; `raidar.verifier`) and its per-step output is the **reward**; an agent is named by Harbor's `AgentName` (`codex`, `claude-code`; was harness `codex-cli`); `environment.type` replaces `runtime.environment`; the headline **metric** (`assessment.metric`) replaces the headline policy. Keep *problem* and *checkpoint* (SCB) and Raidar's *experiment*, *arm*, *condition*, *component*, *factor*, *lock*, *verdict*. Harbor's `oracle` agent (`AGENT_OVERRIDE=oracle`) keeps its name.
- Frozen artifacts keep their bytes and pre-v2 words: the fingerprint sources of released components (listed in each built-in's manifest; so `raidar/oracle/snapshot.py`, `raidar/harness/definitions.py` and the `Harness` CLI ids stay), the grader plugin `raidar/verifier/runtime/raidar_oracle_plugin.py`, the Python pack image recipe (`pack.yaml`, `image/`) and the verifier evidence names inside Harbor trial directories (`raidar-oracle/`, `oracle_leak`, `oracle_bundle`, `oracle-bundle.json`). Released scorers' identities are frozen the same way: the observation subject value `trajectory` (`TRAJECTORY_SUBJECT`, `ObservationSubject.TRAJECTORY`), the evidence input `oracle.cases` and the manifest descriptions of `@1` scorers are hashed into every Assessment key, and the problem store's bundle directory `oracle/` is inside each problem's pinned digest (`scb/forge@38d627ecf668`). Never edit them in place; a change is a new `@version` (components, scorers) or a new pack contract. `tests/test_job_migration.py` fails if a component digest of the pilot moves.
- The experiment is the only authoring unit: one `experiment.yaml` at `experiments/<kind>/<id>/experiment.yaml` (with its lock and `components/`), `schema_version: 2`, naming its `kind` (`ab-test`, `benchmark`, `smoke`; `research-loop` is reserved), one `runtime` (a pack id), pinned `problems`, `agents`, `conditions` (lists of components; optional `shared_components` are put ahead of every condition's own, identically), `arms` (one condition on one agent), `assessment` (`scorers`, optional `metric`) and `analysis` (`baseline_arm`, `attempts`, `seed`, verdict thresholds, `rank_by` for benchmarks). The id is `<runtime>__<subject>__<intent>` (`NAME2`) and the directories are its kind and id (`NAME1`). Do not reintroduce scenario, revision or matrix files.
- Kinds: an `ab-test` compares conditions (`factors` include `condition`; `agent.*` may be added). A `benchmark` is one experiment comparing agents under one condition (factors are `agent.*` only); its baseline arm is the reference agent and its analysis adds a ranking view (mean ± CI, pass@k, cost, tokens). A `smoke` runs the normal engine and its reports are stamped not citable. To compare models, write one benchmark, not a group of experiments.
- Schema v1 files are read-only: `make experiment-validate` accepts them, lock/plan/run refuse them; convert with `make experiment-upgrade EXPERIMENT=<v1> KIND=<kind> EXPERIMENT_ID=<id> OUT=experiments/<kind>/<id>/experiment.yaml`.
- Lifecycle: `make experiment-validate` -> `make experiment-lock` -> `make experiment-plan` -> `make experiment-execute` (each with `EXPERIMENT=experiments/<kind>/<id>/experiment.yaml`; execute also `JOB_ID=`) -> `make experiment-assess JOB=jobs/<id>/<job> STORE=stores/<id> SCORERS="..."` -> `make experiment-analyze JOBS="jobs/<id>/<job>" STORE=stores/<id> ANALYSIS_OUT=analysis/<id>` -> `make review-surface-quality-data QUALITY_JOBS=jobs/<id> QUALITY_STORE=stores/<id>` -> `make review-surface-serve REVIEW_JOBS_ROOT=jobs/<id> REVIEW_STORE=stores/<id>`. Rescoring and analysis use the assessment settings of the job's lock (the experiment's current lock when its `lock_sha256` matches, else the job's own `job.lock.json`); pass `LOCK=`/`REVIEW_LOCK=`/`QUALITY_LOCK=` only for a lock kept elsewhere (smoke locks live under `.tmp/smoke/`). Old make variable names (`RUN=`, `RUNS=`, `HARNESS=`, `BLOCK=`, ...) fail with their new name.
- Use `make experiment-init EXPERIMENT=experiments/ab-test/<id>/experiment.yaml [PROBLEM=<ref>]` only to start a brand-new experiment; it writes a two-arm ab-test starter and refuses an existing path.
- To test another variant of a treatment, add a condition and an arm inside the existing `experiment.yaml` so it stays paired with the baseline arm. Create a new experiment only for a new question (different problems, baseline arm or analysis plan); do not create a sibling experiment for a variant. Arms may differ only in the declared `factors`.
- Use `make experiment-plan EXPERIMENT=<path>` to inspect an experiment's resolved contract (every trial with its hashes), `make problem-list` to see the registered problems, and `make problem-info PROBLEM=<ref>` to inspect one.
- Any change to an experiment, a component file or a problem pin requires `make experiment-lock` before the next job (`make experiment-execute` refuses a stale lock). Never hand-edit a `*.lock.json`. Each job needs a new `JOB_ID`; a job directory is never reused.
- Runtime-compatibility gate: `make experiment-lock` (and so plan, execute and the smoke targets, whatever `EXPERIMENT_SET` overrides) refuses with field-level `RT0`-`RT6` errors, all at once: unvalidated binding (RT0), binding runtime ≠ experiment runtime or a local `path:` task without `[metadata] raidar_runtime` (RT1), binding imported against another pack contract (RT2), component not covering the runtime or the arm's agent (RT3), scorer or headline metric not covering the runtime (RT4), agent version ≠ pack pin (RT5), no pack for the runtime or pack drift at plan/run (RT6). `make experiment-assess`/`assess-regrade` check scorers and `--bundle` against the job's lock (AS1). Never work around a refusal; fix the design or re-import the binding.
- Lock provenance: a lock's `toolchain` section hashes the Raidar spec code and every locked scorer's implementation (including its imports). Any semantic change under `orchestrator/src/raidar/spec/` or to a scorer module therefore makes every `experiments/*/*/*.lock.json` stale, and `make experiment-locks-check` (part of `make quality`) fails until each is relocked with `make experiment-lock EXPERIMENT=<path>`. Relock the experiments in the same change.
- A scorer, headline-metric, threshold or toolchain relock keeps `lock_sha256` (it covers the execution section only), so existing jobs still match: rescore them into the Assessment store with `make experiment-assess` instead of rerunning agents. A changed `lock_sha256` means a new experiment. Move a pre-v2 job (`run.json`, `trajectories/`) onto its experiment's v2 lock with `make experiment-migrate-job JOB=<job-dir> LOCK=<v2 lock> [EXECUTED_LOCK=<lock>]`, never by editing its files; then rescore it.
- Problems come only from the pinned registry: `make problem-import PROBLEM=<ref>`, then `make problem-validate PROBLEM=<ref>` when `problems/registry/` has no validation report for it. A source key in `problems/sources.yaml` binds one runtime (`runtime:`, default `python`; another runtime's binding would be `scb-<runtime>`). The verifier bundle and held-out tests stay on the host; never place them in an agent workspace or a component.
- Toolchains come from runtime packs (`orchestrator/src/raidar/packs/<runtime>/`, loaded by `raidar.packs.load_runtime_pack`): `make pack-info`, `make pack-build`, `make pack-audit`. Agent images carry no scorer tools, and an agent's `version` must equal the pack pin. Do not start packs for other runtimes until the Phase 1 process is signed off.
- Scoring is offline: `make experiment-assess` writes Assessments to a store outside the job and never re-runs agents. Change a scorer, component or headline metric by adding a new `@<version>`, never by editing a released one in place.
- Real-LLM trials default to agent `codex` with `gpt-6-luna` at `low` reasoning effort. Containers run on OrbStack by default (`DOCKER_CONTEXT=orbstack`). After a stopped job use `make harbor-cleanup JOB=<job-dir>`.
- Exclude component payloads under `experiments/**/components/**` (rules files, skills, starter files) from analysis and code-quality checks by default; they are treatment content delivered to agents, not canonical shared product code.
- Treat `jobs/` (and a legacy `runs/`), Assessment stores (`stores/`), analysis output (`analysis/`), `problems/store/`, `problems/cache/` and `.tmp/` as generated runtime artifacts by default: exclude them from quality checks unless the request explicitly asks to review/analyze them. `experiments/` is tracked (definitions only); `experiments/research_loops/` and `experiments/operational_smoke/` are legacy data and git-ignored.
- Never write jobs or synthetic fixtures into `experiments/`; `make review-fixture-synthetic` writes under `.tmp/review-fixture/`.
- The review surface's user flow and the signals and persona questions it surfaces must not be lost (requirements F12). Layout and navigation may change; Playwright specs may be updated only where the flow legitimately changes, and every signal they assert must still be asserted. Run `make review-surface-test` after review-surface or projection changes; to include real jobs pass `REVIEW_JOBS_ROOT` with one `REVIEW_STORE` for all roots or one per root. Use problem/condition/arm/trial wording in the UI; the review projection (`schema_version=2`) keeps its JSON field names (`runs`, `run_json`, `harness`, `headline_policy`), and the surface its routes (`/runs/:runId`) and `data-run-id` attributes, as an internal contract.
- Task completion requires `make quality` to pass.

## Smoke Testing

- Smoke targets run the smoke experiment and the agent benchmark through the normal experiment path (lock under `.tmp/smoke/`, jobs under `jobs/`) on OrbStack. Use `make orchestrator-smoke`, `make agent-smoke` and `make smoke-agents` without setting implementation env vars manually.
- Use the public `make` targets for smoke runs rather than invoking Raidar implementation commands directly.
- Default single smoke (`codex` + `gpt-6-luna` low): `make orchestrator-smoke`
- Single smoke with an explicit agent: `make agent-smoke AGENT=codex PROVIDER=openai MODEL=gpt-6-luna REASONING_EFFORT=low TIMEOUT_SEC=300` (agent versions default to the pack pins)
- One smoke trial per pack agent: `make smoke-agents`
- Codex-only smoke arm: `make smoke-agents SMOKE_ARM=codex`
- Claude-only smoke arm: `make smoke-agents SMOKE_ARM=claude`
- Single Claude Code smoke: `make agent-smoke AGENT=claude-code` (defaults to `claude-haiku-4-5` with no reasoning effort). Claude Code trials run only on `claude-haiku-4-5` without `REASONING_EFFORT`.
- An empty override unsets the field: `REASONING_EFFORT=` (and `EXPERIMENT_SET='agents.0.reasoning_effort='`) leaves the effort unset; `''` sets an empty string.

## Secrets

- Secrets live in the Infisical project `mac-os-cf` (env `dev`), bound by `orchestrator/.infisical.json`. Setup: `infisical login` in a real terminal (interactive).
- Secret-using targets (`experiment-execute`, smoke targets, `experiment-assess`, `jev-shadow-rubric`, `agent-validate`, `component-probe-trials`) run under `infisical run` when the CLI is installed and logged in, else fall back to `orchestrator/.env`. `SECRETS=infisical|dotenv` forces a source.
- `orchestrator/.env.example` lists key names only. Never print secret values; use presence or length checks. Do not delete `orchestrator/.env` without user approval.
- `raidar run` preflights credentials (presence only) for every selected arm before any trial and fails naming the `agents.<i>.name` field.

## Performance (N1 overhead budgets)

- The enforced overhead check is `make perf-gate`: the no-LLM fixture (`make perf-fixture`) at fixed concurrency 1 and 3, each checked strictly against the accepted budgets in `docs/reboot/overhead-baseline.md` §5. It needs Docker (OrbStack; check `orbstack-data-status` reports `external_available=True` first), so it is a release/gate check and is not part of `make quality`. Run it before a phase gate or release and after changes to the execution path.
- `make perf-check JOB=<job-dir>` on real jobs is report-only: it lists every phase against its budget, prints breaches as warnings with the job's trial concurrency and contention, and exits 0. Malformed input still fails. Use `PERF_STRICT=1` only when a strict check of a real job is wanted.
- Do not re-baseline or change budgets to make a run pass. A budget structure change (such as a concurrency-scaled budget) needs user approval and is recorded in `overhead-baseline.md` §5.
