# Homepage Experimentation Log

## Objective

Run the homepage scenario benchmark matrix for:

- `codex/gpt-5.4-mini`
- `codex/gpt-5.4-high`
- `anthropic/claude-opus-4-6`

If none pass, iterate the homepage scenario with `auto_researcher` until at least one benchmark passes. Then run a second research loop for `codex-cli` + `codex/gpt-5.4-mini` low so it matches or exceeds the best passing homepage benchmark score.

## Current Plan

1. Establish the current benchmark baseline for the requested models.
2. If all baseline runs fail, launch a homepage-scenario research loop and rerun the benchmark after each revision.
3. Once at least one benchmark passes, launch a second research loop targeted at `codex-cli` / `codex/gpt-5.4-mini` low.
4. Keep this file updated after every experiment, bug fix, or architecture decision.

## How To Check In-Flight Work

Use the objective and loop state as the source of truth:

- `make auto-research-status OBJECTIVE_ID=<objective-id>`
- `make auto-research-report OBJECTIVE_ID=<objective-id>`
- Inspect `auto_researcher/objectives/<objective-id>/objective.yaml`
- Inspect `auto_researcher/objectives/<objective-id>/loops/*/state.json`
- Inspect `experiments/benchmarks/` for the current benchmark baselines
- Inspect `experiments/research_loops/` for active research-loop artifacts

Treat any loop with status `queued`, `running`, `review_pending`, or `iterating` as in flight.

## Bugs Found

- Mini benchmark timed out at the Harbor trial stage after the agent spent its remaining budget on a second screenshot-cleanup pass instead of finalizing the required verification and close-out. The run never produced a valid scored summary.
- `auto_researcher init` had a Click signature mismatch in `auto_researcher/src/auto_researcher/cli.py`, causing the objective bootstrap to reject `--goal` until the callback accepted the option kwargs.
- The first `auto_researcher` draft for `homepage-reliability` drifted away from the actual homepage scenario and proposed an unrelated smoke starter. I did not approve that draft because it would have changed the objective shape instead of fixing the observed timeout behavior.
- Docker Desktop dropped its socket during the revised benchmark run. The failure was environmental, not scenario-specific, and the daemon had to be force-restarted before new Harbor runs could proceed.
- `bun run capture-screenshot` failed inside the starter because the spawned dev server resolved `next dev` directly instead of an explicit `bunx next` invocation. That left the post-screenshot check incomplete even though the visual-regression verifier itself could capture screenshots.
- The benchmark crops showed the generated page was too tall relative to the reference, especially in the hero and footer regions. That pushed the footer out of the expected visual crop and kept the visual score below the pass threshold.
- The final benchmark matrix produced no pass. Mini/high failed visually, and opus timed out before scoring, so the homepage scenario still needs another revision cycle rather than a second-loop handoff yet.
- `homepage-reliability-compact` was previously misaligned with the real homepage scenario contract. Its metadata pointed at a validation placeholder draft even though the objective-local `homepage-implementation/v001` draft already matched the canonical scenario exactly; that contradiction is now repaired and the objective is awaiting scenario approval.
- `next.config.ts` did not pin `turbopack.root` or `outputFileTracingRoot`, which let Next infer the wrong workspace root during screenshot capture and fail the benchmark on startup.
- The approval baseline is running against the current dirty worktree, so the benchmark now reflects transient local edits rather than a clean committed snapshot. That is acceptable for the current loop, but it means repeated approvals are only comparable if the worktree stays in the same state.
- The Codex CLI adapter currently maps `codex/gpt-5.4-mini` without a reasoning-effort suffix, so a true `mini low` follow-up objective will need an adapter or naming change before it can be expressed directly.
- `codex/gpt-5.4-mini-low` was not expressible before this pass. I added the alias and aligned the adapter/matrix tests so the low-effort target can now be benchmarked directly.
- The homepage prompt did not explicitly tell the agent to assert the header nav and feature-card copy in `src/test/homepage.test.tsx`, which let the run pass visually while still failing requirement mapping. That gap is now closed in the scenario prompt.
- The first low-effort objective draft used bare `tsc --noEmit` in the starter `lint` script, which failed the clean baseline because `tsc` was not on PATH. I switched that starter to `bunx tsc --noEmit` and confirmed the draft starter commands pass.
- The low-effort objective needed manual metadata repair before approval would start: the draft scenario ref, scenario slug/name, review ref, and frozen metrics had to be supplied explicitly. The approval baseline is now running from the repaired metadata.
- The first approval baseline could keep running after the tmux session was torn down, leaving an orphaned stale `make`/`approve-scenario` tree. I killed that tree and restarted the baseline so later results are not contaminated by stale-snapshot repeats.
- The active low-model control point is still a surrogate scenario package rather than the canonical `homepage-implementation` contract. The current research loop is healthy, but strict parity conclusions should still be taken against the canonical contract rather than this surrogate until it is re-anchored.
- The second approval attempt showed the prompt still under-specified the hero and footer exact-string assertions. I expanded the prompt again so the test contract now names every required copy token explicitly.
- A fresh approval baseline is now running from `20260327-153734Z__homepage-implementation__v001__codex-cli__codex-gpt-5.4-mini`; earlier benchmark artifacts should no longer be used for pass/fail decisions.

## Preliminary Failure Hypotheses

- The homepage prompt likely under-specifies the hidden contract surface: section components, shared UI primitives, no inline styles, and atomic-commit discipline.
- The scenario likely needs an explicit test authoring requirement because `test:coverage` is a required gate and the starter coverage bar is already enforced.
- The visual contract likely needs stronger layout guidance or clearer thresholds, because the pass policy is strict and the starter page is only a placeholder.
